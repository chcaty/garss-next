# 拾阅

挑选信息，慢慢阅读。仓库名保持 garss-next。

GitHub Actions 采集 RSS，GitHub Pages 展示文章与管理来源，Flutter 手机客户端读取经过校验的 JSON。新仓库不继承旧 Git 历史。

## 目录与语言

- `collector/`：Python RSS 解析、条件请求、并发采集、历史合并和去重。
- `web/`：TypeScript 阅读页；来源管理页采用 React + Headless UI + Tailwind CSS，单独打包，不影响手机 APK。
- `app/`：Flutter / Dart Android 客户端。
- `sources.json`：唯一的公共采集来源配置。`enabled: false` 会停止 CI 采集。
- `tools/`：校验、采集、静态构建、数据分支发布。

模块职责、行为保持重构的范围与验证记录见 [重构记录](docs/REFACTORING.md)。

## 分支与发布

`main` 只保存源码、测试、依赖锁文件和来源配置。`rss-data` 是由 CI 管理的独立滚动快照分支：每次只有一个根提交，使用 `--force-with-lease` 校验旧版本后替换，绝不合并回 main。每次采集保留当前与前一份不可变 JSON 快照；备份 artifact 保留 14 天。分支替换限制可达历史，GitHub 对不可达对象的物理回收不由项目控制。

Pages 采用 GitHub Actions artifact 部署，不需要 gh-pages 分支。修改网页只构建发布，不采集；采集流程更新数据后调用发布流程。每天北京时间 06:00、13:00、17:00、22:00 触发，另外支持手动触发。失败时保留已发布数据；部署失败可以单独重试。

来源管理页支持编辑、新增、停用、删除、筛选、批量启停与 OPML 导入导出。草稿只存浏览器，不会自动采集。默认在页面检查改动，再前往 GitHub 确认一次来源请求。无需填写 Token 或手动合并 PR：Issue 由仓库所有者创建并确认后，CI 校验改动、提交 sources.json 到 main，并显式触发采集。GitHub 登录仅发生在 GitHub 页面。普通读者的建议不会自动修改公共配置。

请求只包含来源补丁与逐来源版本哈希，保留远程无关改动；同一来源冲突时停止整批应用。重复请求幂等，导入和批量操作自动分批，单个链接不超过 6500 字符、每批最多 40 个来源。请求串行排队，不取消已排队批次。校验失败保留原配置并给出处理日志；普通 Git push 拒绝覆盖并发提交。配置成功提交后，workflow_dispatch 使用 CI 自带的 GITHUB_TOKEN 启动采集，无需浏览器保存凭据。复制或下载 JSON 手动提交仍可使用。


## 数据契约

保留 v1 manifest / SHA-256 校验接口。文章 ID 按保守规范化后的原文链接生成；普通锚点和明确追踪参数不影响身份，内容查询参数和 hash 路由保留。`source_ids` 保存多个来源归属，信息流只显示一篇；不按标题去重。摘要、图片缺失时沿用历史有效内容。近 30 天文章加每个启用来源至少最近 5 篇；文章发布时间晚于当前日期不纳入。

来源配置、采集状态、文章数据分开；手机的关注是本机筛选偏好，不改变公共采集配置。App 已提供信息流、稍后读、订阅源、设置，以及独立同步记录入口；支持来源轮换、未读筛选、批量已读撤销、连续专注阅读、字体调整、离线收藏和浅色/深色/系统外观。阅读来源隐藏无文章项，来源管理显示健康和归档状态。收藏使用新项目本机格式，不迁移旧收藏。

```sh
python -m venv .venv

pip install -r requirements.txt
PYTHONPATH=collector python -m unittest discover -s tests -q
python tools/validate_sources.py
npm ci

npm run build
python tools/collect.py --previous data-checkout --output data-next
python tools/build_site.py --data data-next --output build/site
```

PowerShell 中先设置 `$env:PYTHONPATH = "$PWD/collector"`，再运行 Python 测试。输出目录必须不存在，避免覆盖源文件或上一次有效数据。

Android：在 `app` 目录运行 `flutter pub get`、`flutter analyze`、`flutter test`、`flutter build apk --release --split-per-abi`。ARM64 包适合现代安卓手机。

## GitHub 初始化

创建公开仓库 garss-next；推送 main 与经过校验的迁移种子 rss-data；在仓库 Settings → Pages 选择 GitHub Actions。第一次运行 Collect RSS and deploy 完成实时采集与发布。来源配置中的 repository 信息、App 的默认 JSON 地址需与实际仓库保持一致。

本项目迁入的源码与素材来自 `https://github.com/chcaty/garss`，不包含历史提交、生成的 README、旧快照、邮件配置、密钥或 SDK 缓存。字体许可证随文件保留。上游根目录未发现统一许可证；迁入并不新增或改变原有文件的授权。

## 来源发现与生命周期

`discovery-sources.json` 配置外部 OPML 目录，目前接入 17 个独立出处、34 个 OPML 目录文件。新增 15 个出处的清单文件在 2026-10-03 核对时均有近三个月内的提交，证据链接与核对时间随配置保存；原有两个出处保留分类覆盖，未标为近期核实。新增内容涵盖人工智能、网络安全、数据工程、开源生态、公共资讯、国际新闻、中文资讯和阅读。网页「发现出处」单独显示每个项目、分类、更新证据、目录读取状态和待确认来源数量。维护时间来自清单文件提交，不用 README 更新代替。CI 每 7 天发现一批，单次最多验证 20 个新地址、4 路并发；通过后进入「待确认」，需要在网页加入草稿并提交到 main 才会开启采集。候选最多 100 个，失败验证记录最多 500 条，失败地址 30 天后可重新验证。外部目录失败会保留原候选并在 24 小时后重试。

`api/v1/source-state.json` 保存连续失败次数、首次失败、最近成功和复查时间。连续失败至少 3 次且持续 24 小时后归档，停止普通采集，每 7 天复查；成功后自动恢复。大面积失败（80% 及以上）不累计归档次数，全部活跃源失败则停止发布并保留旧数据。手动停用的源不参与复查。网页「请求复查」生成配置中的 recheck_requested_at，提交生效后立即复查；修改 RSS 地址同样重置归档状态。

归档记录保存在 `api/v1/source-archive.json`，外部发现保存在 `api/v1/source-discovery.json`；两者随 rss-data 滚动保存，不新增历史分支。sources.json 始终保留人工配置，归档仅改变有效采集/阅读目录。归档不是永久删除，网页仍可编辑、复查或删除配置。

来源管理区使用 Headless UI 的 Tabs、Listbox、Menu、Dialog、Checkbox、Switch，支持键盘和焦点管理。草稿保存基线；远程配置变化时先合并远程更新并检查改动，同一字段保留本机值。复制、下载与打开 GitHub 不代表配置已发布。

发现目录按分类轮流分配验证名额，优先补足候选较少的类型。目录配置变化会立即触发一次发现，无需等待一周。指定的社交源每次发现都会重试，普通失败地址仍按 30 天冷却处理。

微博热搜与微信 24h 热文通过公开 RSSHub 实例采集；后者来自第三方今日热榜，并非微信官方全站榜单。allow_undated 只用于明确配置的热榜源，缺少发布时间时保存首次发现时间并标记 date_inferred；历史合并保留首次时间，重复采集不把旧条目刷新成新文章。今日头条热点频道暂不可用，保留在发现验证名单，验证通过后进入待确认。

重复订阅地址只保留一条配置。source_aliases 记录合并的旧 ID，用于历史条目合并、旧来源链接重定向与已读记录的 legacy_ids 兼容；配置校验会拒绝再次加入相同地址（忽略普通 URL 锚点与域名大小写）。同站点的不同 RSS 栏目仍允许独立保留。

网页统一提供信息流、订阅源、同步记录入口，外观可跟随系统或手动切换浅色/深色。稍后读和已读进度保存在当前浏览器；稍后读保存标题、摘要、原文链接和来源分类，退出公共目录后仍能查看。Web 未提供离线启动保障，已经打开的页面在公共目录读取失败时可以展示本机稍后读。专注阅读展示 RSS 摘要并提供原文链接。`api/v1/sync.json` 记录最近 30 次已发布采集，运行中或未发布的失败任务通过 GitHub Actions 查看。

Web 旧版本只保存收藏 ID，升级后会为仍在目录内的旧收藏补齐内容；已经退出目录且未备份的内容无法恢复，会显示未补齐数量。存储失败时明确提示当前改动只在本次会话有效。Android 的旧收藏分类在来源元数据仍可用时补齐，新收藏保留保存时分类。清除浏览器数据或卸载 App 会删除相应本机记录，两端不自动同步。

信息流与稍后读保留独立筛选，稍后读可以只看未读。打开摘要即标记已读，两端都支持恢复未读，兼容 `legacy_ids` 的已读状态。Android 另提供批量已读撤销、来源轮换、字号和图片设置；公共配置仍由 Web 管理。文章显示时间、来源管理时间和今天／近 7 天边界使用北京时间。

来源审查显示字段原值和新值，合并远程更新前列出同字段、删除或新增 ID 冲突，核对后采用本机值。提交页逐批标记是否打开确认页，并提供「检查发布结果」：先核对公共目录，再通过 GitHub 公开只读接口检查配置应用和采集状态。无需 Token，访问失败或次数受限时保留草稿并提示查看日志。只有全部改动出现在公共目录后才更新本机草稿基线。Issue 关闭表示配置已应用、采集已启动，不代表部署完成。

快照中的 `collection_status` 区分公共停用、自动归档与采集健康，`enabled` 仍表示是否参与有效采集。Android 同步记录从同一批次的健康状态、来源目录和采集记录读取状态与名称，支持搜索；缓存兼容缺少该字段的旧快照。

产品名称与网页、App 图标统一为拾阅：打开的书页与书签。外观入口使用图标并提供可访问名称。Android 按 ABI 分包，版本 0.2.1+3。

## 阅读筛选与参考项目

网页和 App 支持分类、今天、近 7 天、全部时间，与来源、搜索和未读筛选组合使用。时间边界按北京时间计算；共享文章保留多个来源/分类归属。来源选择显示未读数。App 使用可滚动筛选面板，选择应用后返回原列表；网页提供 J/K 移动和切换文章、Enter/O 打开、F 加入稍后读、/ 搜索和 Esc 返回。输入框、输入法组合和外观菜单不拦截文字输入。

本次调研参考 FreshRSS、Miniflux、Read You 和 Folo，具体采纳理由及维护证据见 [产品参考](docs/PRODUCT_REFERENCES.md)。实现沿用 GitHub CI + Pages + JSON，不引入账号后端或其他项目的代码。

手机 Web 将来源、分类、时间和排序收进可搜索的筛选面板；桌面保留来源索引。信息流／稍后读均可叠加「只看未读」并记住各自条件，移出稍后读提供 8 秒撤销。两端专注阅读固定队列操作，显示本次筛选的位置；Android 阅读来源改为可搜索的原生底部面板。

Web「公共订阅」与 Android「本机关注」明确区分；本机关注可叠加采集异常等状态。公共改动审查依次核对改动、在 GitHub 提交、检查实际发布结果，手动备份默认折叠。同步页面独立读取各区块，失败显示未知数量并提供相应重试，不把缺失状态显示为零。
