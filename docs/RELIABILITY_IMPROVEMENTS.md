# 本机记录保护、读取优化与内容发现

## 范围

基于 main `7706ed52d3745085f5119ac77f63ed7af5c4aaef`，保留 Python 采集、静态 v1 JSON、Web 和 Flutter 客户端架构。源码来自该提交，全部 151 个 Git blob 均校验，初始树与上游 `eb879bf2b1499c74de617f97f483e0b9739703e4` 一致。

这些改动仅在本地验证。没有推送、PR、合并、部署或实时采集；`sources.json`、`discovery-sources.json`、工作流、应用签名和凭据均未改动。没有证据表明用户此前实际丢过数据。

## 第一批：保护阅读记录

### Web

- `garss-reading` 原始字符串始终保留。整份 JSON、单条收藏、可选字段或未知版本损坏时，保留能读取的内容，暂停记录改动。
- 恢复前可下载包含精确原始字符串的备份。用户确认后，先写入并校验独立隔离副本，再确认已处理的具体损坏字节。备份或恢复中断不会覆盖原记录。
- 新记录使用原子、独立 UUID 键的操作日志，第一次操作与旧格式基线一起写入。标签页互不覆盖整库；逻辑时钟、同版本删除优先及别名关系处理收藏删除、恢复未读、迁移和撤销。
- 标签页同步、窗口重新可见时刷新状态。旧版页面改写迁移前数据会触发冲突提示，不能静默丢弃任一版本。升级后请重新加载旧标签页。
- 收藏 ID 迁移只改变身份，保留原标题、摘要、链接、日期和分类；旧页撤销不会替换另一页重新保存的内容。

操作日志没有不安全的自动清理或跨标签页压缩。历史较长时，启动/改动时的扫描成本与存储量会增加；筛选和搜索不访问日志。配额不足时停止新改动并提示导出。未来若要压缩，必须先设计跨标签页事务协议；本轮没有引入数据库迁移。旧客户端不能直接读取 v3 新操作，降级前必须保留原始导出和浏览器数据。

### Android

- 本机收藏整体或单条损坏时，不自动覆盖 `saved-v2`。提供明确提示和「备份并恢复」入口；备份验证失败时不替换原记录。
- 存储读异常与写入返回 `false` 均明确处理。恢复和迁移通过可替换存储边界测试中断场景。
- 仅保存实际变化字段，收藏写入失败不会阻止无关已读、关注或显示设置持久化。
- 「本机关注」由用户隐藏偏好决定，独立于公共停用/归档状态；关注开关保留用户意图。阅读流仍按公共有效采集状态筛选，关注归档来源不意味着继续收到文章。

## 第二批：减少重复处理

### Web

- 目录及收藏修订时构造搜索文本、分类/来源集合、时间戳和两个稳定排序；每次筛选只扫描已构造的索引。
- 只重用本页面曾完整校验、且 manifest 地址、快照 ID、时间、文件字节数及 SHA-256 均一致的目录对象。未知对象、改变的文件摘要或混批元数据不能触发短路。
- 新增「检查更新」，区分公共采集与本机检查时间；刷新失败保留旧目录，重复/乱序返回不能替换较新的页面状态。

真实样本来自 rss-data `0e9af415139df455d5e8d510f49d7f98298800e4`，生成于 2026-10-13 09:10:48 UTC：13,260 篇文章、238 个来源，articles.json 未压缩 11,531,638 字节，Git blob `a1defcf5b6848bb6b770d0567dfc57b7b29838b9`。

Node 24.19.0 CPU 模型基准，8 组组合条件、预热后 136 次：

| 项目 | 旧实现 | 索引实现 |
| --- | ---: | ---: |
| 查询中位数 | 13.87 ms | 0.97 ms |
| 查询 p95 | 24.43 ms | 1.46 ms |

一次索引构造约 46.14 ms，所有查询结果逐 ID 比对一致。这是本机模型测量，不是浏览器帧率、网络速度或手机性能保证。运行环境与数据分布都会影响结果。

完整文件 fixture 校验加载读取 11,618,306 字节；同快照复查只读取 metadata + manifest 978 字节（共两次请求）。该数字是 fixture 原始字节数，不是 HTTP 压缩后流量。

可复现：

```sh
node tools/benchmark_reading.mjs /path/to/articles.json /path/to/feeds.json
```

### Flutter 与读取边界

Flutter 的 SHA-256 校验、UTF-8/JSON 解码、模型构造及本地 JSON 序列化使用后台 isolate；目录索引、稳定时间排序和状态相关统计避免重复计算。只复用当前 repository 实例完整验证过的内存目录，磁盘缓存的快照 ID 不能代替验证。冷启动仍需校验并下载公共快照。

相同实际样本的 Dart 3.13.2 CPU/模型基准，以固定原始文章 ID 选取 2,000 条收藏和 3,000 条已读，组合真实关键词「技术」「Python」「AI」、分类、来源、未读、近 7 天与收藏条件；30 轮查询和统计从 5,822.14 ms 降至 1,211.35 ms（约 4.8 倍）。8 组结果的 ID 集合和时间顺序均一致；其中 3 组的同时间文章次序改为稳定保留输入顺序，其余 5 组逐 ID 顺序一致。这是一次本机测量，包含结果数组构造，不代表界面帧率或移动设备耗时。基准脚本为 `app/tool/benchmark_library.dart`。

首次加载仍读取完整 v1 目录；Web 的 JSON 解析和索引构造仍有一次性主线程成本，搜索索引也占用额外内存。Android 原有单文件 20 MiB 上限保留。轻量索引、摘要分片、后台 Web 解析和数据库改造不在本轮范围，不能把查询基准改进推断为无限扩容能力。

## 第三批：内容发现与健康度

新增字段均可选，不改变 v1 必填字段和快照完整性校验。旧客户端可以忽略这些字段。

- `health.raw_entry_count`：解析出的原始条目数
- `health.valid_article_count`：保留策略应用前，日期、标题、链接有效并去重后的文章数
- `health.new_article_count`：与该来源上一份保留快照比较，本次首次出现的规范化链接数；在历史合并前计算
- `health.last_new_article_at`：发现新文章的本次采集时间，不是文章发布时间；无新增时保留上一值
- `health.drop_reasons`：日期缺失/无效、未来日期、不安全/缺失链接、缺标题、重复链接、超出保留期

“请求完成但无可读文章”与“有内容但本次零新增”分别提示；低频更新不会仅因零新增被归档。失败检查不伪造当前有效条目数。

候选显示最多 3 条安全 HTTP(S) 样文、最新文章时间、验证状态和统计时间。加入草稿时只复制可编辑来源字段，质量统计和样文不会写进公共配置。14 天验证时效独立于每周外部目录读取；失败复查至少间隔 1 天，保留上次样文和通过时间，连续失败 30 天须有实际失败复查后才淘汰。空内容复查更新当前质量统计；网络失败保留旧统计并标明其时间。

总检查预算仍为每轮 20 个、4 路并发，为过期候选预留 5 个名额，空余额可用于另一类检查。满 100 个候选仍检查新地址；只有成功的新候选可替换已有候选，优先替换失败、过期或较早项目。目录下载失败本身不会清空已知好候选。

来源状态额外给出按 RSS 主机与 HTTP 状态聚合的观察，最多 20 组，每组最多列出 100 个 ID。已发布归档样本确认 `rsshub.v2fy.com` 的 21 个来源均为 HTTP 404；它只能支持共享上游异常诊断，不能证明这些原站停更。本轮没有修改这些来源地址或激活候选。

主题订阅包、保存智能筛选、摘要分片/数据库、正式 Android 签名和跨设备同步留作独立后续范围；优先完成现有保护、效率与质量闭环。
